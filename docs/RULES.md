# 競技ルールと採点

## プログラム

- Python 3標準ライブラリで実装する。
- メモリ上限は子プロセスを含む128MiB。swapは使用不可。
- 前処理・入力・出力を含む全体を測定する。
- 各データセットを5回実行し、すべて正解・制限遵守なら実行時間中央値を採用する。
- 出力は問い合わせ順の整数1行ずつ。正解と完全一致すること。
- C/C++、Numba、Cython等への移植やネイティブコード化は禁止。
- 外部実行ファイルによる計算代替、外部計算資源、計測環境や時計への干渉は禁止。
- 特定データの答えを埋め込まず、問題仕様を満たす任意の入力に対応する。

公開データは練習と模擬本番用です。最終評価は別のデータを用いるため、1種類だけに通用する改善では十分でない場合があります。

## 高速化率

`基準プログラムの中央値 ÷ 自分のプログラムの中央値`

基準10.0秒、自分2.0秒なら5.0倍です。開発中に改善を確かめるための指標で、正式な処理性能点ではありません。同じコードでも計測値には揺らぎがあります。

## 正式な処理性能点

データセットごとに、全5回が正解し、制限を守ったチームだけを有効とします。有効な各チームの実行時間中央値を集め、さらにその中央値を`T_ref`とします。

`P = 100 × T_ref / (T_ref + T_team)`

例として、各チームの中央値が3秒・5秒・7秒なら、T_refは5秒です。

| チーム | 中央値 | 性能点 |
|---|---:|---:|
| A | 3秒 | 62.50 |
| B | 5秒 | 50.00 |
| C | 7秒 | 41.67 |

偶数チームでは中央2値の算術平均をT_refとします。誤答、メモリ超過、実行失敗、出力違反等はそのデータセット0点で、T_refから除外します。有効チーム1つなら50点です。有効チーム0の場合は評価環境の正常を確認したうえで全チーム0点となります。

複数データセットの性能点は、同じ重みで算術平均します。評価環境の不具合、基準側の異常、運営者による中断は0点ではなく、再実行が必要な未完了状態として扱います。

正式点は全チーム分が揃った後に講師が計算します。自分のbench/mockだけでは確定しません。

## 総合点

`Score = 0.90 × sqrt(P × E) + 0.05 × R + 0.05 × O`

- P：処理性能点
- E：技術評価点
- R：チーム間評価点
- O：情報共有点

すべて0～100点です。技術評価等は講師の案内に従います。未入力の評価点を0点とみなして総合点を出すことはありません。

## 提出物

最終プログラム、改善実験レポート（Markdown/TXT）、発表資料（PDF）をZIPで提出します。READMEは任意です。レポートには仮説・変更・AIへの相談と検証・測定・考察を残してください。失敗した実験も学習成果になります。
